# 智能体对话与机场地图联动

## 用户行为

智能体返回本轮分析结果或补参信息后，提取已识别的设备名称、设备编号，定位到设备对应的机场。这里的机场就是巡检设备在平台设备库中的机场，飞行器编号会通过 `parentSn` 或机场的 `subDeviceSn` 找到所属机场。

- 唯一匹配：地图飞到该机场，显示名称和状态。
- 相机围绕机场地面坐标定位，而非只飞到其正上方后倾斜朝向别处；已知地形高度时使用地形高度作为目标中心。
- 同名机场：全部显示，包括离线机场，视角覆盖所有匹配位置。
- 在线使用平台原有蓝色机场图标，离线使用灰色图标；未知状态明确标注“状态未知”。
- 坐标相同的多个机场：标记做屏幕像素偏移，标签错开，不修改真实坐标。
- 缺少合法坐标：在对话面板提示，不能用零坐标或推测坐标代替。
- 显示“陆水湖无人机”等别名时，沿用后端已确认的设备别名规则。
- 新建对话或点击“清除定位”时，仅删除智能体的定位覆盖层，不删除平台原有图层。
- 地图定位只读取设备目录，不调用创建、发布、起飞或飞控接口；任务执行时的在线检查保持独立。明确的 `task.live.open` 事件仍可打开原飞行实时页面，普通设备提及不会进入飞控页。

已识别的结构化设备信息优先于文字推测；不存在结构化信息时，匹配本轮用户文字、智能体结果中提及的设备。航线候选和识别目标候选不会作为设备编号使用。

“科信局机场在哪里”“陆水湖机场在哪”等单纯位置问答现由后端直接读取平台目录，保存到该用户会话中，返回正式名称、状态和坐标。回答的 `content[].metadata.airportFocus` 同时供地图使用，不再让大模型凭记忆猜测机场，也不重复请求另一份定位结果。创建任务、航线请求和结构化确认消息不会被这条位置查询流程接管。

任务参数、位置问答和地图共同使用 `oge-agent/app/ga_skills/shared/device_names.py` 的设备名称匹配规则：支持正式名称、行政前缀简称、无人机/机场/设备/机巢称呼、项目已确认的陆水湖别名，以及“三号/3号/机场3”等编号写法。名字匹配始终依赖当前设备目录；编号不同不互相替代，多个匹配仍保留选择或全部展示。

## 接口

`POST /ai/v1/agent/airports/resolve`

请求头沿用平台登录：`Authorization: Bearer <平台令牌>`。平台认证模式下，读取目录也使用同一用户令牌，保持平台的数据权限。

```json
{
  "text": "中试谷机场在哪里？",
  "references": [
    {"deviceName": "中试谷机场"}
  ]
}
```

`text` 最长 16000 字符，`references` 最多 50 项；每项可传 `deviceName`、`deviceSn`，均最多 256 字符。前端优先从 `clarification.lowAltitude.args`、设备候选和 `content[].metadata.facts.skillResults[].data` 提取。

响应示例（模拟数据）：

```json
{
  "airports": [
    {"deviceSn": "example-one", "name": "同名机场", "longitude": 113.9, "latitude": 29.7, "onlineStatus": 1},
    {"deviceSn": "example-two", "name": "同名机场", "longitude": 113.91, "latitude": 29.71, "onlineStatus": 0}
  ],
  "unlocated": []
}
```

`onlineStatus`：1 在线，0 离线，null 未知。`unlocated` 包含匹配到但坐标不可用的设备名称和编号。响应不包含联系人、电话号码等无关信息。401 表示未登录或令牌失效，502 表示无法读取平台目录。接口不会新增 SSE clarification 类型。

## 本地验证

1. 后端终端 Ctrl+C 后，重新运行 `D:\OpenGA1013\whulri-agent\start-backend.ps1`。
2. 刷新 9000 端口的新前端，用原平台账号登录。
3. 可询问“中试谷机场3在哪里”“中试谷机场在哪里”“陆水湖附近的设备在哪里”，检查定位与在线、离线图标。
4. 有同名机场时检查是否全部展示；缺坐标时检查是否提示。

自动检查：前端 `node --test tests/airport-focus.test.cjs`；后端 `pytest tests/test_airport_focus.py tests/test_airport_location_answers.py`。前端地图联动测试 7 项通过；后端已覆盖位置问答、别名、任务流程、认证及模型额度回归。前端打包通过。全量类型检查仍有仓库原有错误，新改动文件未出现类型错误。

内置预览浏览器缺少 WebGL，未完成真实 Cesium 画面的视觉验收，需要在平时使用的平台浏览器上验证。模拟预览页保存在 `tests/airport-focus-preview.html`，只用于开发检查，不作为产品入口，也不会打入主页面。
